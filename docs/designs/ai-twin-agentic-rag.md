## Problem Statement

The portfolio chatbot today (`src/app/api/chat/route.ts` → `src/lib/vertex.ts`, UI in `src/components/chat-widget.tsx`) puts all of `src/content/site.ts` + `projects.ts` into one system prompt and talks *about* Rakib in third person. It has no retrieval, no citations, no fact check, English only, text only.

The goal is a portfolio showpiece: a first-person **AI twin** that visitors (recruiters, technical interviewers, freelance clients, with depth adapting to who's asking) can talk to as if messaging Rakib. It answers in detail about him and his projects, grounded in his documents. It understands Bangla, Banglish and English, takes voice and images, sends project screenshots back, and works like a social messaging app.

## What Makes This Cool

- A recruiter taps the mic, asks in Banglish "tumi last company te ki korecho?", and gets a confident first-person answer in Banglish with numbered sources. They can tap play to hear it in a Bangla voice.
- A CTO uploads a screenshot of a dashboard and asks "what did you build here?". The twin recognizes the project, explains the architecture, and replies with two more screenshots from the same project as message bubbles.
- Any bubble can be swiped (mobile) or long-pressed/hovered (desktop) to reply to it. "Explain this part more" resolves against the quoted message.
- Live step chips (Planning… Searching 4 docs… Checking facts…) and a collapsible "How I answered" panel (plan, sources, critic verdict) show the LangGraph agent at work. The wait becomes the demo.

## Constraints

- **LLM provider: Google Vertex AI (Gemini) only**, authenticated with the user's GCP service account (being added to the project). Reason: HF Inference free credits are about $0 for free accounts as of Oct 2026 (PRO gets $2/mo), which a 4-5-call-per-message agent loop would burn through fast. No Hugging Face in v1.
- Frontend stays the existing Next.js 15 / React 19 / Tailwind 4 site on Vercel.
- Vercel serverless request bodies are capped at about 4.5 MB, so images and audio must be compressed on the client before upload.
- Secrets never enter git. `.gitignore` ignores `.env`, `.env.local`, `.env*.local` and `service_account.json` / `*.serviceaccount.json` / `*-service-account.json` (corrected in eng review, outside voice #12). `.env.example` IS tracked and today holds a real-looking `RESEND_API_KEY` and the real GCP project id (commits `bd8ecc4`, `7ff4cb4`). Rule from now on: only `.env.example` and `twin-agent/.env.example` may be committed, with placeholder values only. Service-account JSON, `TURNSTILE_SECRET`, `TWIN_SESSION_SECRET`, `IP_HASH_SECRET` and `ADMIN_PASSWORD_HASH` live only in Vercel env, Secret Manager, or local `.env.local`.
- The corpus is small (about 300-1,500 chunks), so no hosted vector DB is needed.

## Premises (agreed)

1. Brain = Gemini on Vertex AI through the service account. No HF in v1.
2. First-person "AI twin", clearly labeled as AI in the UI. It never commits to salary, start dates, availability, rates or offers, and routes those to the real Rakib through lead capture.
3. Grounding is mandatory. Every factual claim must trace to a retrieved chunk. The critic rewrites or removes unsupported claims, and if support is missing the twin says it doesn't have that in its notes and offers direct contact.
4. The RAG index is built at build time and baked into the deploy artifact. Sources: site content, CV PDF/docx, Project Portfolio docx, blog MDX, public GitHub READMEs, and a new first-person notes file.
5. The chat UX is a social-messaging shell: mic tap, gallery/camera, agent-sent images, reply-to-any-message, streamed step chips, a trace panel.
6. Reply language mirrors the visitor (Bangla script / Banglish / English, with a toggle). Technical terms stay in English. Banglish is transliterated to Bangla script before TTS.
7. Phased rollout. Phase 1 ships the full chat shell plus the text brain.
8. The agent is a **LangGraph** graph (user-directed).

## Approaches Considered

### Approach A: LangGraph.js inside Next.js
One repo and one Vercel deploy, reusing `vertex.ts`. Rejected: user prefers the mature Python LangGraph ecosystem (LangSmith tracing, Studio) and the stronger Applied-AI-engineer signal.

### Approach B: Python LangGraph service on Cloud Run + Next.js frontend (CHOSEN)
FastAPI + LangGraph (Python) on Cloud Run in the same GCP project as the service account. Next.js is the chat UI and proxies to it.

### Approach C: LangGraph.js now, portable to Python later
Rejected along with A.

## Recommended Approach (B)

### Topology

```

  ▼
Next.js on Vercel  /api/twin/chat, /api/twin/tts, /api/twin/lead

  │  - forwards client IP (x-vercel-forwarded-for) as X-Twin-Client-IP

  ▼
Cloud Run service "twin-agent" (private, IAM-invoker = Vercel SA only)
  FastAPI ── LangGraph graph ── Vertex AI (Gemini, embeddings) / Cloud TTS
  index baked into image: chunks.jsonl + vectors.npy + bm25.pkl + media catalog
```

### LangGraph graph

State: `messages` (last 12 turns, client-held, **untrusted**), `reply_to` (quoted message id/role/text + media description, **untrusted**), `input_media` (the current turn's image or audio bytes, inline in the request, never stored), `lang_mode` (`bn` | `banglish` | `en`, plus override), `intent`, `plan` (sub-queries + tools), `chunks[]`, `media_out[]`, `draft`, `critique`, `revisions` (0-2), `trace[]` (step events streamed to the UI).

```
START
 └► normalize_input
      ├─ audio → transcribe (Gemini audio in → transcript + detected language)
      └─ image → vision_read (Gemini: describe; extract visible text as DATA; match to media catalog/projects by embedding)
 └► detect_language   (Unicode Bengali range → bn; Latin + Flash classifier → banglish|en; UI override wins)
 └► guard             (Flash, structured output: injection | off_topic | commitment_request | abusive | ok)
      ├─ commitment_request → handoff_reply (+ lead card) → END
      ├─ off_topic/abusive  → steer_reply → END
 └► route             (fast_path: greeting/contact/thanks → templated grounded reply → END)
 └► plan              (Flash: sub-queries, written in English for retrieval since the corpus is mostly English, plus tool choices)
 └► retrieve          (per sub-query: hybrid vector + BM25 → RRF → top 6; tools: get_project(slug), show_media(project|query))
 └► draft             (first person, lang_mode, cites [n] by chunk id, uses reply_to as explicit context)
 └► critic            (Flash, structured: unsupported_claims[], persona_violations[], commitment_violation, language_ok, score)
      ├─ pass → respond
      ├─ fail & revisions < 2 → draft (with critique)
      └─ fail & revisions == 2 → respond with unsupported sentences removed + "I don't have that in my notes" line
 └► respond           (stream final text in chunks + citations + media_out + trace summary) → END
```

- Models are env-configured (`TWIN_MODEL_FAST`, `TWIN_MODEL_MAIN`), defaulting to the latest GA Gemini Flash for every node. A Pro-class model for `draft` is an opt-in experiment, judged by evals.
- Embeddings: Vertex multilingual Gemini embedding model, so Bangla and Banglish queries also embed sensibly next to the English translation.
- **Client history and `reply_to` are untrusted.** The client can forge "assistant" turns or quoted text, so no turn is signed or trusted [eng review D1: signing cut]. Rules: (a) all prior turns, whatever role they claim, are rendered as a transcript block marked "visitor-supplied, unverified". (b) History and quotes are wrapped as quoted data in prompts ("the visitor quoted: …"), never as instructions, and are never used as grounding. Only retrieved chunks ground claims. (c) The guard classifies the current message plus the quoted text together. (d) Caps: 12 turns, 1,000 chars per historical turn, 1,000 chars for the quote.
- **Media lifecycle (stateless).** Uploads are processed inline and discarded. Image or audio bytes travel only with the turn they are sent in. `vision_read` / `transcribe` output (description, extracted text, transcript) comes back in the SSE `meta` event, and the client stores it on that message. The thread in `localStorage` keeps a local thumbnail (data URL, ≤ 30 KB) plus that description, never re-uploads past media, and a `reply_to` that quotes an old image sends its stored description. Agent-sent media are public `/twin-media/...` URLs from the catalog.
- `show_media` can only return entries from `media.yaml`. The twin cannot invent image URLs.
- Images the visitor uploads are treated as untrusted. Any text inside them goes to the drafter as quoted data, never as instructions.
- Latency budget (estimate, to verify): normalize/guard/route about 0.8s, plan about 1s, retrieve about 0.3s, draft about 2-3s, critic about 1s. Roughly 5-7s with no revision, with the first step chip under 1s. Each revision adds about 3-4s. A hard 15s wall-clock cap in the graph forces the fallback path (strip unsupported sentences and respond) whatever the revision count. The target revision rate is < 20%, tracked in logs. The final answer is generated before the critic runs, so the text "streams" after approval: chips cover the wait, then the approved text is chunked out. Fast-path replies skip plan/critic.

### Chat shell (Next.js, client)

- Floating launcher on every page plus a full-screen `/chat` route (layouts per viewport: design 6A).
- Bubbles with avatar + AI tag, grouped time dividers, sending→sent tick (no seen) [design 3A/3B], typing indicator, an "AI twin" badge in the header and a one-line disclosure on first open.
- **Reply-to**: swipe right (touch) or hover/long-press → "Reply". A quoted preview sits above the composer and the sent message shows the quoted snippet. Tapping the quote scrolls to the original.
- **Attach**: `<input type="file" accept="image/*">` for the gallery and `capture="environment"` for the camera. The image is resized on the client (canvas, max 1600px, JPEG q≈0.8, target < 1 MB) and EXIF is stripped.
- **Mic tap**: tap to record (MediaRecorder; `audio/webm;codecs=opus`, `audio/mp4` fallback for iOS Safari), live timer and waveform, tap to send, swipe to cancel, max 60s.
- **Agent media**: image bubbles from `media_out`, tap for a full-screen lightbox with caption and project link.
- **Voice out**: play button on each twin message (`/api/twin/tts`), plus an "auto-play replies" toggle that defaults to on when the visitor used the mic.
- Step chips while working, numbered citations linking to `/work/[slug]` or the source, and a collapsible "How I answered" panel.
- Language toggle (Auto / বাংলা / Banglish / English) as a header pill [design 6B].
- The thread lives in `localStorage` (message ids, text, media URLs). The last 12 turns plus the quoted message go to the server each request, so the server stays stateless in v1.
- Handles empty, error and rate-limited states, retry, and "twin resting" when the budget cap is hit (the contact card still works).

**Waiting bubble** [design 2B]. One twin bubble changes over time:
```
t=0ms (client, before server)  (●) [◌ Planning…]
t≈1s                           (●) [✓ Planning] [◌ Reading my notes…]
t≈3s                           (●) [✓ Planning] [✓ Reading my notes] [◌ Checking facts…]
critic revision                (●) … [◌ Rechecking a claim…]
answer starts                  (●) I led a 6-person team at … [1][2]
                                   ─────────────────────────────
                                   How I answered · 4 sources · 6.2s ›
```
- The current chip has a spinner. Finished chips are `--color-text-faint` with a check. Chips crossfade, with no slide or bounce.
- The first chip is rendered on the client the moment send is pressed, which covers cold starts. Server `step` events then take over.
- On the first `token` event the chip row collapses into the "How I answered" line at the bottom of the same bubble. That line opens the trace (1b) and shows only the source count and time in 1a.
- Text appears in chunks at about 30ms per word. Under `prefers-reduced-motion`, the whole answer appears at once.

**Bot check** [design 2C, phase 1b]. Turnstile runs in managed/invisible mode when the chat opens. Only when Cloudflare asks for an interactive challenge does its widget render inline above the composer, with send disabled and the label "Verifying you're human…". If it's blocked or fails, the twin posts a bubble ("I couldn't verify your browser. You can still reach the real me:") with the contact card.

**AI labelling and handoff card** [design 3A]. Every twin bubble group shows the 28px avatar with a 14px "AI" tag (`--color-accent-soft` fill, `--color-accent` text), so a cropped screenshot is still labelled. The handoff card is the only bordered card in the thread (`--color-border-strong`, `--radius`), with a person icon and the title "Talk to the real me" / "আসল আমার সাথে কথা বলুন" / "Real amar sathe kotha bolun". It lists Contact form (`/#contact`), email as selectable text with a copy button, and LinkedIn. No avatar sits on it, because it is not a twin message.

**Bubble chrome** [design 3B]. No seen or read receipts. A centered `--color-text-faint` time divider appears only after a gap of 5+ minutes ("Today 3:42 PM"). Visitor bubbles show a small sending→sent tick.

**Surfaces and motion** [design 4A]. The chat inherits the site system in `src/app/globals.css`:
- The panel uses `--color-bg-elevated` with a 1px `--color-border-strong` border. No `shadow-*`, `ring-*`, `backdrop-blur` or `hover:scale` (removes `chat-widget.tsx:72,78` styling).
- Twin bubbles use `--color-surface` with `--color-text`. Visitor bubbles use `--color-accent` with `--color-bg` text.
- The panel opens with the existing `page-in` keyframes plus a 12px rise, eased with `--e`. Bubbles enter over 0.45s with `--e`. Chips only crossfade over 150ms. There is no bounce or scale anywhere.
- All motion is disabled by the existing `prefers-reduced-motion` block.

**Typography** [design 5A]. `src/app/layout.tsx` adds Anek Bangla through `next/font/google` (variable `wght`/`wdth`, subset `bengali`, CSS `unicode-range: U+0980–09FF`). It is exposed as `--font-bangla` and placed in `--font-sans` right after Archivo, so Latin text keeps Archivo and Bengali characters get Anek Bangla. Any element with `lang="bn"` gets `line-height: 1.75`. Chat body text is 16px minimum (1rem), never smaller.

**Citations** [design 5B]. Inline markers render as superscript numerals in `--color-accent` (¹ ²), with no square brackets. Tap or keyboard focus opens a popover with the source title and a link (`/work/[slug]`, CV PDF, blog post or repo). Esc closes it and returns focus to the marker. The full source list lives in "How I answered" (1b).

**Gestures and accessibility** [design 6C]:
- Swipe right to reply works only when the swipe starts at least 24px from the screen edge.
- Long-press opens a menu: Reply / Copy / Play (Play from phase 3).
- On desktop, a Reply icon appears on hover and on keyboard focus.
- Keyboard: ↑/↓ move between messages, R replies to the focused message, Esc cancels a quote or closes a popover or the lightbox, Enter sends, Shift+Enter adds a new line.
- The thread is `role="log"`. A completed answer is announced once through an `aria-live="polite"` region. Streamed tokens are not announced, and step chips are announced politely.
- The lightbox is a dialog with a focus trap that returns focus to the opener.
- Tap targets are ≥44px and body text contrast is ≥4.5:1 (`--color-text` on `--color-surface`).
- Playwright runs axe on the opened, waiting, answered and error states.

**Launcher** [design 7A]. A 56px circle with Rakib's real photo (tight face crop from `public/profile-photos`), a 2px `--color-accent` ring and a 16px "AI" tag at the bottom-right. **Voice UI** [design 7B, phase 3]:

### Voice

- In: the audio goes straight to Gemini in `normalize_input`. No separate STT vendor.
- Out: Google Cloud Text-to-Speech with `bn-IN` voices for Bangla and `en-IN`/`en-US` for English. Banglish replies are transliterated to Bangla script by a Flash call before TTS. Audio is cached in the GCS bucket `twin-tts-cache` keyed by `sha256(voice + text)`, so all Cloud Run instances share it. The bucket has a 30-day lifecycle rule.

### Production hardening

- **Session gate (phase 1)**: the client renders Cloudflare Turnstile with `NEXT_PUBLIC_TURNSTILE_SITE_KEY` when the chat opens. `/api/twin/session` verifies the token with `TURNSTILE_SECRET` and sets an HttpOnly, Secure, SameSite=Lax cookie holding a JWT signed with `TWIN_SESSION_SECRET` (`sid`, `exp` = 2h). Every `/api/twin/*` call forwards it as `X-Twin-Session`, and Cloud Run verifies signature and expiry (it holds the same secret from Secret Manager). Missing or expired → 401, and the client silently re-runs Turnstile and retries once.
- **Rate limits + spend cap (phase 1)**: enforced in Cloud Run with Firestore counters keyed by `HMAC(IP_HASH_SECRET, client_ip)` and by `sid`: 20 msgs/hour and 60/day per IP (IPv6 keyed by /64); no per-session limit [D15]. The global daily spend cap (`TWIN_DAILY_USD_CAP`) is computed from Vertex `usage_metadata` token counts × a per-model price table in `twin-agent/app/pricing.py` (updated when model env vars change). When it is exceeded, the graph short-circuits to the "twin resting" reply plus the contact card, and the UI shows that state. Also: upload MIME sniffing, image ≤ 1.5 MB / audio ≤ 60s & 1 MB, a 2,000-char text cap, and the guard node for injection, jailbreak and off-topic messages.
- **Evals**: `evals/golden.yaml` has about 50 questions (20 EN, 15 Bangla, 15 Banglish), each with `must_include` facts and `must_not` claims. `evals/redteam.yaml` has about 15 jailbreak, impersonation and commitment probes. `evals/run.py` runs the real graph and scores fact recall, groundedness (LLM judge), language match and zero commitments.
  - Evals call the graph in-process with `TWIN_LIMITS_BACKEND=memory`. Rate limits, the spend counter and session checks use an in-memory no-op store, so CI needs no Firestore access and never touches production counters or triggers "twin resting". Logging to Firestore is off (`TWIN_LOG_CONVERSATIONS=false`).
  - CI: a GitHub Actions workflow on PRs touching `twin-agent/**`, `content/twin/**`, `src/content/**`, `scripts/export-content.ts`. It authenticates to GCP through Workload Identity Federation (`twin-ci-evals`, no JSON key), runs `export-content` then `build_index.py` (fresh index), then `evals/run.py` at temperature 0.
  - Gate = the Success Criteria numbers: per-language fact recall ≥ 90%, language match ≥ 95%, and zero fabricated entities or commitment violations on redteam. Variance policy: a failing case is re-run twice and counts as failing only if 2 of 3 runs fail. Hard gates (fabrication or commitment) fail on any single occurrence.
  - Cost: about 65 cases × ~5 calls on Flash per run, capped at once per PR push (concurrency group cancels superseded runs).
- **Observability**: structured JSON logs to Cloud Logging (request id, node timings, token usage, critic score). LangSmith tracing is optional through env.
- **Conversation logs + insights (phase 4)**: Firestore `conversations` stores `HMAC(IP_HASH_SECRET, ip)` (keyed, not reversible by brute-forcing IPv4 without the secret), lang, question, answer, sources, critic score, latency and an `unanswered` flag. A Firestore TTL policy deletes them after 90 days. The chat's first-open notice says: "I'm Rakib's AI twin. Chats are stored for 90 days to improve answers. Don't share sensitive info." A private `/admin/insights` page shows top questions and knowledge gaps. It follows the single-enforcement-point rule: the Next.js page is only UI and proxies `/api/twin/admin/*` to Cloud Run (same IAM ID token). Cloud Run verifies the password against the bcrypt `ADMIN_PASSWORD_HASH` (Secret Manager), enforces 5 login attempts/15 min per HMAC'd IP in Firestore, issues a signed admin token (HttpOnly cookie set by the proxy, 12h), and is the only component that reads `conversations`. Vercel keeps `run.invoker` only.
- **Handoff (phase 1)**: when the guard sees a commitment request (salary, dates, offers, rates), the twin replies that the real Rakib handles that and renders a static contact card: links to `/#contact`, `mailto:`, LinkedIn. No form yet.
- **Lead capture (phase 4)**: the card upgrades to an in-chat form (name, email, message). It posts to the existing `/api/contact` with a fixed `subject: "[AI Twin lead] <first 60 chars of the visitor's question>"` (that route requires a non-empty subject), and the message body appends the last 6 turns of the chat for context.
